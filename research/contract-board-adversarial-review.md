worktree. Read the complete `ASTRA.md`, current implementation checkpoint,

## Acceptance findings handed to the progression owner

1. **Rejected mobilisation changes the selected rig.** The reviewed
   `src/game/progression.js:714`–`726` calls `selectRig()` before checking travel
   affordability. A fresh Node reproduction generated the actual contract
   `ct-iberian-quarry-core-6pabn` with seed 5031, set cash to zero, held all
   certificates and owned all rigs. `acceptContract()` returned
   `{ok:false, reason:'Mobilisation costs 2571'}` while the selected rig changed
   from `crawler-lite` to `core-rig`; contract remained null. This is an API
   transaction issue; the contracts screen must show the rejection and remain
   open, but cannot make the API atomic itself.
2. **Reaccepting the current job resets completed work.** On a fresh state,
   accept the actual first starter generated by
   `makeContractBoard('nordic', 1, makeRandom(20260905), 5)`, whose id is
   `ct-nordic-auger-8mbn8`. Set the live run's `holesDone` to 1 and `revenue` to
   123, then call `acceptContract()` with that same contract. Both acceptance
   calls return `ok:true`; the second run has `holesDone:0, revenue:0`.
   `progression.js:729`–`756` replaces the accumulator without an active-run or
   idempotency guard. Screen double-dispatch prevention is also needed, but
   does not protect acceptance from another screen or a return to the board.

Both findings were reproduced against the source available to this worktree
before the independent progression-reliability changes. They are not claims
about that task's newer implementation. No progression source was edited here.

## Content requirements checked against the real consumers

- `data.js:4537`–`4558`: estimated hours include drilling, setup, tripping and
  applicable HDD reaming/pullback. The old label “Estimated on tools” is too
  narrow; keep an explicit job estimate label.
- `data.js:5998`: `unitNoun` describes what `holes` counts. A deterministic
  sweep of 300 contracts per region at level 60, seed 9035, encountered all
  21 methods and the existing nouns hole, pile, anchor, column, position,
  bore, raise, heading, drive, ring and well. Use those nouns, with a neutral
  length label; do not call every target vertical depth or every unit a hole.
- `economy.js:1490`–`1520`: quoted payout is the base tender. Completion and
  grade affect it; time/quality bonuses, penalties and role/skill/reputation
  multipliers affect settlement. No net-profit or guaranteed-final-pay claim
  follows from `payout` alone.
- `economy.js:1495`–`1503`: time bonus requires completion of the settlement
  slice and falls to zero at its effective deadline; quality is scaled to
  100% for S, 60% for A, 25% for B, otherwise zero. **This is not a whole-job
  completion gate.** `progression.js:781`–`797` apportions bonus and deadline
  into a one-hole contract; `completeHole()` settles that slice with
  `holesCompleted:1` at `progression.js:913`–`931`. Show the supplied components
  as possible base bonuses, not promises of final additional cash.
- `economy.js:1530`–`1536`: `reputationReward` is the base; grade, skills and
  role modify the final value.
- `shell.js:202`–`230`: normalization preserves original fields and supplies
  `methodId`, `regionId`, `requiredCerts`, `targetDepth` and `deadlineHours`.
  Passing the complete normalized object to `progression.acceptContract()`
  preserves the fields its authoritative acceptance path requires.
- `economy.js:543`–`555`: bolt and driven-pile settlement also have delivery
  units. A quoted comparison rate divided by contract metres is valid when
  labeled as such; it must not imply that this is the settlement increment.

properties defined in `styles.css`/`motion.css`; there are no missing colour,

wrapping instead of the old card clamps. No definite production CSS defect was
established by this source review.

Two instrument details require care before interpreting a layout pass:

- Offscreen scroll content has real untrimmed Range rectangles that can cross
  the header/actions geometrically even though the scroller clips it correctly.
  Overlap checks must compare fragments intersected with viewport and ancestor
  clip boxes. Permanent clipping checks must retain the original rectangles;
  dropping all scrollable content would hide real layout faults.
- Global `.toasts` uses `z-index:80` and `pointer-events:none`, above sheet
  `z-index:70`. `elementFromPoint()` therefore cannot prove the absence of a
  visual toast covering a sheet. Target hit tests prove interaction access;
  visible toast rectangles require a separate overlap check or an explicit
  evidence limitation.

Actual 320/390 px font rendering, long-header body height, filter/certificate
wrapping and failed-acceptance alert visibility were deferred to the prepared
browser states. Those states were subsequently captured and reviewed below;
no pixel values are inferred from this CSS review.

## Executed stale-results callback reproduction

The preceding source finding is now reproduced at callback scope. This is
**execution of the unchanged callback extracted from the real shell source,
not execution of the full DOM/UI shell**. There is no fake DOM implementation.
Vite's existing `parseAst` identifies the actual `on(EVENTS.HOLE_COMPLETE, …)`
callback; its source slice is evaluated with controlled closure variables and
a `show` recorder. The real event bus, real progression, generated starter and
native Node microtask queue execute the interaction. The shell callback is
registered before `progression.init()`, matching the production order documented
beside that callback.

Measured source: `src/ui/shell.js:783`–`815`.
SHA-256 of the exact extracted callback in this worktree:
`b92140fb119f798b21bdf34169fa17236c310110fa3d05803134ac448d467962`.

Result: stale `{runId:1, attemptId:2}` after current attempt 3 returns null
from `completeHole()`. Full `serialise()` output remains byte-for-byte equal,
cash stays EUR 4,500, `holesDone` stays 0 and attempt 3 stays pending. The actual
shell callback nevertheless calls `show('results', …)` once with stale attempt
2. This demonstrates an unwanted navigation request; it does not claim a
browser-rendered results screen.

Run the following code through `node --input-type=module` from the private
worktree (for PowerShell, put it in a single-quoted here-string and pipe that
string to Node). It does not write files, start a browser or change packages.

```js
import fs from 'node:fs';
import crypto from 'node:crypto';
import assert from 'node:assert/strict';
import { parseAst } from 'vite';
import {
  createGameState, createBus, makeRandom, EVENTS, SCENES,
} from './src/core/contract.js';
import { createProgression } from './src/game/progression.js';
import { makeContractBoard } from './src/game/data.js';

const source = fs.readFileSync('src/ui/shell.js', 'utf8');
const matches = [];
function walk(node) {
  if (!node || typeof node !== 'object') return;
  if (node.type === 'CallExpression'
      && node.callee?.type === 'Identifier' && node.callee.name === 'on'
      && node.arguments?.[0]?.type === 'MemberExpression'
      && node.arguments[0].object?.name === 'EVENTS'
      && node.arguments[0].property?.name === 'HOLE_COMPLETE') {
    matches.push(node.arguments[1]);
  }
  for (const value of Object.values(node)) {
    if (Array.isArray(value)) for (const child of value) walk(child);
    else if (value && typeof value === 'object') walk(value);
  }
}
walk(parseAst(source));
assert.equal(matches.length, 1);
const callbackSource = source.slice(matches[0].start, matches[0].end);
const showCalls = [];
const makeCallback = new Function('SCENES', 'show', 'queueMicrotask',
  `let holeSettling=false; let pendingLevelUp=null; return (${callbackSource});`);
const callback = makeCallback(SCENES, (scene, params) => {
  showCalls.push({ scene, runId: params.result.runId,
    attemptId: params.result.attemptId });
}, queueMicrotask);

const state = createGameState(), bus = createBus();
bus.on(EVENTS.HOLE_COMPLETE, callback);
const progression = createProgression({ state, bus, rand: makeRandom(1) });
await progression.init();
const c = makeContractBoard('nordic', 1, makeRandom(20260905), 5)[0];
assert.equal(progression.acceptContract(c).ok, true);
const stale = progression.beginHole(c);
const current = progression.beginHole(c);
state.scene = SCENES.SITE;
const payload = { contract: c, ...stale, depth: c.targetDepth, grade: 'S',
  breakdown: { time: { parSec: 100, actualSec: 40 } } };
const before = JSON.stringify(progression.serialise());
const directReturn = progression.completeHole(payload);
assert.equal(directReturn, null);
bus.emit(EVENTS.HOLE_COMPLETE, payload);
await new Promise((resolve) => queueMicrotask(resolve));
const unchanged = before === JSON.stringify(progression.serialise());
assert.equal(unchanged, true);
assert.equal(showCalls.length, 1);
assert.equal(showCalls[0].scene, SCENES.RESULTS);
console.log(JSON.stringify({
  scope: 'Extracted actual callback execution; no DOM or browser',
  startLine: source.slice(0, matches[0].start).split('\n').length,
  endLine: source.slice(0, matches[0].end).split('\n').length,
  callbackSHA256: crypto.createHash('sha256').update(callbackSource).digest('hex'),
  stale, current, directReturn, progressionUnchanged: unchanged,
  money: state.player.money, holesDone: progression.run.holesDone,
  currentAttemptPending: progression.run.holePending, showCalls,
}, null, 2));
```
